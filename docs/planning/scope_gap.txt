Built, but not in the v1 scope
A material share of the repository implements a consumer file-drive product: folder tree with drag and drop, starring, trash with 30-day retention, context menus, suggested files and folders, drive statistics, persistent chat sessions with attachments, an offline mode and a PWA shell.
None of it appears in §2 or §3. §4 sets v1 as operator and officer facing, and §10 exists specifically to stop unplanned additions. This is not an argument to delete the work — it is an argument to get it recorded, either as an accepted change request or as deliberate out-of-scope, so the estimate against the milestones stays honest.
Escalate before the next sprint is planned
The three §11 hard rules have no implementation and no test
No uncited Q&A answers. No identity or legal link promoted to the verified layer without a human confirmation event. No handwritten-source verified data without human confirmation. These are product-level acceptance gates for v1, not features to bolt on at the end — and two of the three depend on data structures that do not exist yet.
Air-gapped acceptance is binary, and currently unreachable
§3.10 makes zero outbound network calls a release blocker, verifiable by egress monitoring. Today every LLM call and the reranker send document text to external APIs, and there is no local model path. This blocks M5 and depends on assumption A2 (GPU availability), which should be confirmed now rather than at hardening.
Fix naming, config and provenance columns before more data lands
The §6 table-naming standard, the
sys_dg_config
table, and page and region coordinates on every extracted fact are one migration today. After ingestion at volume they are a migration plus a backfill plus a re-extraction of everything already processed.

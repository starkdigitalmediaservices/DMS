# T81 — licensing enforcement: assumptions pending real business sign-off

T81 was blocked on A5 ("Licensing model decision finalised before M4") — no tier
names, limits, or enforcement mechanism were ever specified anywhere in the
SoW, backlog, or codebase. Per the user's explicit instruction (2026-08-26,
overriding the recommended "leave it blocked" default — see the session's
`feedback-blocked-task-override` pattern), this was built against a
**reasonable placeholder model**, not the real one. Every number and mechanism
below is an assumption, live-verified to work mechanically, not a decided
business term. Replace before this reaches a real customer.

## What was built

Two independent enforcement mechanisms, picked by `DEPLOYMENT_MODE`:

- **SaaS** (`deployment_mode=saas`, default): usage metered live against a
  subscription plan. Enforced at the one real metered action — document
  upload (`document_service.upload_document`) — via
  `license_service.check_saas_capacity`. Blocks new uploads only; existing
  documents remain fully readable, searchable, and exportable regardless of
  plan/trial state, deliberately, since this is an evidence system and
  locking access to legal records over a billing lapse is a worse outcome
  than a grace period.
- **On-prem/air-gapped** (`deployment_mode=on_prem`): cannot phone home to
  check a subscription without violating T92's egress-zero guarantee, so
  capacity is granted instead by a signed license file, verified offline via
  Ed25519 (`license_service.verify_license_signature`, zero network calls).
  Generated by `backend/scripts/generate_license.py` (vendor-side, holds the
  private key — never ships inside the product image). Installed via
  `POST /api/v1/billing/license`, status via `GET /api/v1/billing/license`.
  Missing/invalid/expired licenses get a `LICENSE_GRACE_PERIOD_DAYS` (default
  14) grace window before uploads are blocked, mirroring SaaS trial expiry.

Both mechanisms are wired through `license_service.check_upload_allowed`,
called once at the top of `document_service.upload_document` — covers both
the single-file and bulk upload endpoints, since bulk calls the same function
per file. `LICENSE_ENFORCEMENT_ENABLED=false` disables enforcement entirely
(useful for dev/test).

## Explicitly not built (scope boundary, not a bug)

- **Seat/user limits**: no per-seat metering, because there's no user-invite
  endpoint in the codebase at all today — `sign_up` is the only place a
  `User` row is ever created (one tenant = one admin user). Adding seat
  limits without a multi-user flow to enforce them against would be
  meaningless. If/when a user-invite feature is built, this is the natural
  place to add a `max_seats` check.
- **Node/GPU capacity enforcement**: the on-prem license payload carries
  `max_nodes`/`max_gpu_count`, but nothing compares them against the actual
  deployment (would require reading Helm chart replica count or a Kubernetes
  API call from inside the app, which also cuts against T92's egress-zero
  posture depending on how it's implemented). Fields exist so a real license
  format doesn't need a breaking migration later; comparison logic is
  future work.
- **Billing UI**: no frontend surfaces subscription/license status yet — only
  the backend API (`GET /billing/subscription`, `GET/POST /billing/license`).
  A blocked upload today surfaces as a generic 402 to the existing frontend
  upload flow, with the real reason in the response body but no dedicated UI
  treatment.
- **Payment processing**: nothing here charges anyone anything. This is
  capacity gating only, not a billing/invoicing system.

## Live verification performed (2026-08-26)

All against the real running dev stack, not just unit tests (which also all
pass — `backend/tests/test_license_service.py`, 9/9, plus the full existing
121-test suite unaffected):

- Signed up a real tenant via `POST /api/v1/auth/sign-up` → confirmed a trial
  subscription auto-created with the documented limits via
  `GET /api/v1/billing/subscription`.
- Uploaded 100 real documents via `POST /api/v1/documents/` → the 101st got a
  real `402` with the exact limit-reached message; confirmed existing
  documents stayed listable/downloadable (real `200`, real presigned URLs)
  while blocked.
- Generated a real signed license via `scripts/generate_license.py`, switched
  the running backend to `on_prem` mode, installed it via the real
  `POST /billing/license` endpoint → status flipped to `active`.
- Tampered with a byte of the signed payload and re-installed → real `400`
  with the exact signature-mismatch reason.
- Backdated an installed invalid license past the grace window in the DB →
  confirmed a real `402` on upload, and confirmed reads still returned `200`
  throughout every blocked state above.
- Reverted the environment back to `saas` mode and confirmed the SaaS trial
  block was still correctly in effect (103/100 docs — usage is computed live
  from real `Document`/`DocumentVersion` rows, not a counter, so it can't
  drift from what was actually uploaded during the on-prem detour).

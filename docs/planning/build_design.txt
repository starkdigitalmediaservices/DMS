Words you will see
read once, then skip
Terms from the Scope of Work that appear throughout. Nothing here is jargon for its own sake — each one names something the product has to do.
Word
What it means here
fact
One value pulled out of a document — a name, an area, a date. Facts are what we check, cite and export.
region
The rectangle on the scanned page that a fact came from. Lets us highlight the source.
provenance
Where something came from: which file, which page, which spot on the page, from which office, and when. We say “source location” in this document.
machine / human-verified
Two states for a fact. Machine means the software read it. Human-verified means a person accepted it. Only the second counts as evidence.
adjudication
The Scope of Work’s word for the review queue: anything the software could not decide, waiting for a person.
corpus / collection
One set of documents, usually from one office or one register series.
held link
A link between two records that is probably right but not confirmed. Usable in the product, shown with a badge, kept out of exports.
7/12 extract (satbara)
The Maharashtra land record showing survey number, holder, area and crop. One of the document types we will be reading.
ferfar
A mutation entry — the record of a change of holder, usually after a sale, succession or court order.
shuddhipatrak
A correction issued later against an earlier entry. Corrections are why records need an amendment chain.
sanad
A grant or title deed issued by government. Links from a sanad are legal links, so a person must confirm them.
khatedar
The holder named in a land record.
shera
The remarks column in a register.
survey no. / CTS no.
How a plot is identified — survey number in rural areas, City Survey (CTS) number in towns.
guntha · are · hectare
Area units used side by side in these records. 1 hectare = 100 are; 1 guntha ≈ 101 sq m.
register
The old bound books these documents come from. Their layout is why the four handlers exist.
spread
One entry printed across two facing pages.
ditto mark
A mark meaning "same as the row above" instead of repeating the value.
air-gapped
Installed on a network with no internet at all.
PDF/A
A version of PDF meant for long-term archives. Required on ingest, with the original file kept too.

The split under processing is the important part. Searching and checking happen side by side, not one after the other. A document can be found as soon as it is processed. Checked facts build up behind it at human speed. Only checked facts may be exported, certified or used in legal work.
2 · Where each fact came from — agree this first
T04 · T05 · T06
Every fact we store has to point at the exact spot on the page it came from. Three parts of the product draw that spot on screen: the checking screen, the 360 view, and the citations under an answer. None of them can be started until we agree how a spot is described.

Four links, and none may be empty. If a fact has no region, we refuse to save it. A fact we cannot show on the page is a fact nobody can check.
What has to be decided, in writing, before code
Where (0,0) sits
The top-left corner is (0,0) and y grows downward, the way the scan looks. Agree it once, so the extractor, the API and the viewer cannot disagree.
What the numbers mean
Store values from 0 to 1, as a fraction of the page width and height. Not pixels. The box then stays correct at any zoom and any screen size.
Crooked scans
Store the rotation and skew per page and let the viewer apply it. Old registers were photographed crooked. Ignore skew and the highlight lands on the wrong row.
Facts from more than one place
One value can come from two pages. Store a list of regions, not a single one. Build the column as a list from day one.
How we test it
Load a crooked scan. Every fact has a region, every region sits inside its page, and clicking a fact highlights the right part of the image. Then try to save a fact with no region: it must fail.

The blue step is a rule, not a habit. A row becomes human-verified only when a real person accepts it, and the system records who. If the value was handwritten, that person has to confirm it as well. Enforce this where data is saved. Hiding the button in the screen is not enough.
How we test it

The operator sees the scanned Form A page on the left and its fields on the right. Click a field and its area lights up on the scan. Click an area and the field is selected. Both work as soon as the source-location rules exists, and neither works before it. The state column shows the flow from the previous section, one state per row rather than per document.
Two lanes of work
T51
One lane for clean rows accepted in batches, one lane for anything flagged. A row can move between lanes, and every move is logged.
One person per row
T52
Separate queues for notes in the margin, join mismatches, low-confidence fields and handwritten areas. When someone opens an item it is hidden from everyone else, so two people never check the same row.
Keyboard first
T54
An operator should never need the mouse for a clean row. Allow accepting everything above a chosen confidence in one go, and keep that number in config rather than in code.
Checking never blocks search
SoW 3.5
Checking decides what counts as evidence, not what can be found. An unchecked document still appears in search, marked as unchecked.
How we test it
One operator checks fifty rows using the keyboard only. Every accept writes a log entry with the user, the row, the previous state and the confidence. A handwritten row cannot be accepted without confirming it. A second operator never sees a row someone else has open.

7 · Records that change over the years
SoW 3.6 · T60 – T62
A land record is not a document. It is a first entry plus every change made to it since, sometimes over fifty years. Work out the current state from those changes. Never store a current value and edit it in place.

A 1974 Form A entry, a 1998 ferfar transferring it on succession, and a 2021 shuddhipatrak fixing the valuation. Every change points at the page that authorised it, so “why does this record say this?” can be answered with a page image. Legal status sits alongside: in force, set aside, under stay, superseded. A record takes the status of a source that is in court, which is what makes it possible to filter on.
How we test it
Add a shuddhipatrak decades after the first entry, one that changes a valuation from Rs. 1,240 to Rs. 12,40,000. Then check three things: the original view, the current view and the full history are all readable; each one cites its source page; and rebuilding from the chain gives exactly the current view. Write this test first in the records module — it is the one that catches a stored, editable current value sneaking in.
8 · Search, sources, and saying “no answer”
SoW 3.5 · hard rule 1 · T70 · T71 · T73
Search already works. What v1 adds is the rule around the answer: every statement is tied to a passage, and there is no answer at all when the passages do not support one.

This gate is a product rule, not a setting to tune. A confident, well-written answer with no source is exactly the failure this product exists to prevent. Clicking a citation opens the page at the highlighted area, using the same viewer as the checking screen. Build that viewer once.
How we test it
Ask something the documents cannot answer — “which Waqf plots in Washim are under stay?” when no such record was scanned. The system says it cannot answer. Ask something they can: every sentence carries a citation, and each citation opens the page at the right spot. This has to work whichever model provider is configured.

Make the log append-only in the database itself: the application user gets no permission to update or delete rows. The chain turns “our logs say so” into something an auditor can check for themselves. The certificate cannot ship until legal has reviewed the template (assumption A3).
Log everything
T07
Log every change, plus views and downloads. Today only sign-in, search and chat are logged, so widening coverage comes first, before any chaining.
Always know who did it
T08
Refuse any change that has no user attached. A chain full of empty user fields proves nothing.
Six user roles
T50
Six roles: records officer, operator, department head, legal counsel, IT admin, and auditor with read-only access. Department scope is a group over projects, not another folder level.
How long we keep things
T66
How long to keep each class of record, replacing today's single rule of emptying trash after 30 days. The classes and defaults are decision D-7.
10 · Export, duplicates and bulk edits
SoW 3.9 · T78 – T80
Export
T78
CSV, JSON, XLSX, PDF and PDF/A. Every export is logged with the user, what was exported and in which format. It reads only checked data.
Duplicate detection
T79
Compare hashes first. The SHA-256 is already stored but never compared, so the same file is processed again in full today. Then add fuzzy matching for pages scanned twice. Show both to an operator to decide — never drop a file quietly.
Bulk edit
T80
Show a preview before applying, log every row changed, and allow a limited undo. It cannot mark machine values as checked; that only happens on the checking screen.
11 · Two ways we install it
SoW 3.10 · T90 – T93

Both setups use the same four interfaces, so no feature depends on which one is running. Failing closed matters because the alternative is worse: quietly calling a cloud API when the local model is missing would send government records outside, and still look like a working install.
How we test it
T92 · T93
Start everything with outbound network blocked. Loading documents, checking them and searching all still work on local models. Then remove a local model and confirm the call fails instead of falling back to an API. Finally, have someone who did not build it install the whole thing from the runbook.
